# UI visual QA

Работай через `pilot_*` инструменты. Если skill `browser-pilot` ещё не
загружен, загрузи его первым.

## Правила

- Только `http://localhost:3000` (и `127.0.0.1:3000`). Другие origin — только
  по разрешению пользователя.
- Никогда не вводи пароли и не открывай Supabase Dashboard.
- Не задавай `profileDir`; контекст должен быть чистым.
- Для машинной проверки — `pilot_snapshot` и console errors. Скриншот — только
  для человека.
- Не кликай разрушительные действия на реальных данных. Демо и dev-данные —
  можно.

## Сценарий

1. `pilot_navigate` → страница.
2. `pilot_snapshot`; проверь заголовки, кнопки, alt-тексты, что нет пустого
   экрана и «undefined».
3. Проверь viewport 1440×900, 768×1024, 360×800 (reload/resize через браузер
   или отдельные проверки).
4. Тёмная и светлая темы; переключи и повтори snapshot.
5. `prefers-reduced-motion` — анимации не ломают контент.
6. Клавиатура: Tab до интерактивных элементов, Enter/Space, Escape в модалке.
7. Ошибки консоли: `pilot_act` возвращает console errors; зафиксируй.
8. Пины: клик по изображению, маркер, модалка, комментарий; измени размер
   окна — маркер не должен съезжать.
9. Скриншот для отчёта: `pilot_screenshot` (viewport или fullPage).

## Что сверять с `docs/DESIGN.md`

- Палитра, шрифты, стекло/неон, компактность.
- Контраст текста, focus-ring, тач-зоны.
- Горизонтальный скролл доски на мобильном, карточки не ломают layout.
- Статус не только цветом (подпись/иконка).

## Формат отчёта

```
Проверено: ...
Найдено:
- [страница, viewport] проблема → предложение
Console errors: ...
Скриншоты: ...
```

Не отчитывайся «всё ок», если не смотрел мобильный и светлую тему.
