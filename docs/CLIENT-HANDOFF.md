# Передача Neyroflow заказчику

Коротко: **архив с GitHub — это только резервная копия кода**, а не работающий
продукт. Для передачи нужны четыре сервиса и домен. Ниже — простая инструкция.

## Самое короткое

1. Не отдавать только ZIP: без БД, Storage, env и домена он не запустится.
2. Передать аккаунты: GitHub, Vercel, Supabase, Reg.ru.
3. Создать заказчику нового админа, удалить старого.
4. Ротировать `SUPABASE_SERVICE_ROLE_KEY`, `CLIENT_SESSION_SECRET`,
   `CRON_SECRET` и обновить env в Vercel.
5. Проверить `/api/health`, `/demo`, вход, файл и пин.

## Что передаётся

| Что | Где | Зачем |
|---|---|---|
| Код | GitHub, приватный репозиторий | исходники и история |
| Хостинг | Vercel, проект `client-tracker-portfolio` | сайт, cron, env |
| База и файлы | Supabase, проект с БД и Storage | данные, Auth, файлы |
| Домен | Reg.ru, поддомен `client-tracker-portfolio.neyrocontent.ru` | адрес |
| Документация | `README.md`, `docs/DEPLOY.md` | запуск и обновления |

Плюс доступы к аккаунтам через **менеджер паролей** (1Password, Bitwarden и
т.п.). Пароли и ключи не отправляются в чат или обычной почтой.

## 1. Передать GitHub

1. Владелец репозитория: **Settings → Danger Zone → Transfer ownership**.
2. Указать GitHub-аккаунт заказчика, подтвердить.
3. Заказчик принимает приглашение.
4. Репозиторий должен остаться **private**.

Альтернатива: добавить заказчика collaborator с правом Admin, но transfer
чище — аккаунт и история полностью у заказчика.

## 2. Передать Vercel

1. Vercel → Project → **Settings → Transfer Project**.
2. Передать в аккаунт/team заказчика.
3. Проверить, что перенеслись:
   - Environment Variables;
   - Domains;
   - Cron Jobs/Schedules.
4. Если env не перенеслись — заказчик добавляет их заново из `.env.example`.
   Для production:
   `NEXT_PUBLIC_SITE_URL=https://client-tracker-portfolio.neyrocontent.ru`.

## 3. Передать Supabase

Перед передачей сделать backup БД (Supabase → Database → Backups) и проверить,
что файлы Storage не нужны заказчику отдельно.

1. Supabase → Organization → **Transfer project** (или передать всю
   организацию).
2. Заказчик должен стать **Owner**.
3. Проверить: таблицы, RLS, Storage bucket `attachments`, Auth users.
4. Создать заказчику нового админа:
   - Authentication → Users → Add user;
   - SQL Editor: выдать профилю роль `admin`;
   - удалить старого админа.
5. **Ротировать ключи** после передачи:
   - `SUPABASE_SERVICE_ROLE_KEY`;
   - `CLIENT_SESSION_SECRET`;
   - `CRON_SECRET`.
   Обновить их в Vercel и сделать Redeploy. Старые клиентские сессии
   инвалидируются — это правильно.

## 4. Передать домен

Домен `neyrocontent.ru` остаётся у владельца Reg.ru.

- Если домен уже на заказчике — ничего не делать.
- Если домен на вас — передать аккаунт Reg.ru или делегировать домен.
- DNS-запись только для поддомена:

  | Тип | Subdomain | Canonical name |
  |---|---|---|
  | CNAME | `client-tracker-portfolio` | значение из Vercel |

  Apex `@` и `www` **не трогать** — там другие проекты.

Подробно: [docs/DEPLOY.md](DEPLOY.md).

## 5. Что проверить после передачи

- [ ] `/api/health` → `{"ok":true,"db":true,"storage":true,"statuses":6}`
- [ ] `/demo` → 200, два проекта и пины
- [ ] `/login` → вход нового админа
- [ ] `/admin` → доска, создание задачи
- [ ] `/admin/clients` → создание клиента и инвайта
- [ ] клиент открывает инвайт, видит **только свои** проекты
- [ ] файл загружается и скачивается
- [ ] пин на изображении работает
- [ ] колокольчик показывает событие
- [ ] Cron Jobs/Schedules содержит `/api/cron/deadlines`

## 6. Как пользоваться (кратко для заказчика)

### Админ

1. Открыть `https://client-tracker-portfolio.neyrocontent.ru/login`.
2. Войти по email и паролю.
3. **Клиенты** → создать клиента → выдать инвайт → отправить ссылку.
4. **Дашборд** → создать задачу, назначить проект, приоритет, дедлайн.
5. Открыть задачу → загрузить файл или изображение.
6. Кликнуть по изображению → оставить пин-комментарий.

### Клиент

1. Открыть инвайт-ссылку.
2. Нажать «Войти в портал» — пароль не нужен.
3. Открыть проект → задачу → посмотреть файлы и комментарии.
4. Ответить, принять работу или отправить на доработку.

### Демо

`https://client-tracker-portfolio.neyrocontent.ru/demo` — без входа, только
чтение. Можно показывать клиенту до старта.

## 7. Обновления

После передачи обновления идут через GitHub:

1. Заказчик (или разработчик) пушит изменения в `main`.
2. Vercel автоматически собирает и деплоит.
3. Если менялись env — **Redeploy без Build Cache**.

ZIP-архив с GitHub — только для бэкапа. Он **не содержит**:
- `.env.local` и секреты;
- базу Supabase и файлы Storage;
- настройки Vercel и домена.

Поэтому «архив + инструкция по деплою» без передачи аккаунтов не даст
работающий продукт.

## 8. Если заказчик не технический

Два варианта:

1. **Полная передача** — заказчик владеет GitHub/Vercel/Supabase/доменом,
   вы остаётесь на поддержке по договору.
2. **Managed-хостинг** — инфраструктура у вас, заказчик получает URL и админа.
   Это не передача продукта, а услуга; зафиксируйте это в договоре.

Для MVP рекомендуется **полная передача** с ротацией ключей и новым админом.

## 9. Безопасность

- Не отправлять `.env.local`, `service_role`, `CRON_SECRET`,
  `CLIENT_SESSION_SECRET` в чат.
- Пароли — только через менеджер паролей.
- После передачи сменить пароль админа и ротировать ключи.
- Реальные ПДн запрещены: только маскированные/тестовые данные.
- Дисклеймер ПДн уже есть в футере и `README.md`.
